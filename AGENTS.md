# qlblog agent guidance

- Preserve the `notes/`, `blogs/`, `skills/`, and `site/` separation documented in `README.md`.
- This repository is a kgdistiller instance and static consumer, not the kgdistiller product checkout. Keep personal sources, source policy, alignments, private graph state, adopted public export data, frontend, and deployment here. Never vendor or submodule the engine, and never run the engine during a site or Pages build.
- `skills/` is the authority for qlblog-maintained personal and community Skills. New personal Skills default to the top level; create a suite or move/place Skills into one only when the user explicitly requests that exact classification. Downloaded open-source Skills follow the established `community/` convention and stay out of the website. After every reclassification or parent-directory move under `skills/`, rerun the linker of every agent runtime installed on this machine: `skills/link-codex-skills.sh` / `skills/link-claude-skills.sh` on POSIX/WSL, or `skills/link-codex-skills.ps1` / `skills/link-claude-skills.ps1` on native Windows.
- Cross-runtime availability is the default for `skills/`. Runtime-exclusive Skills live in the scope directories `skills/codex-only/` (Codex-native subagent and external-runtime Skills, skipped by the Claude Code linker) and `skills/claude-only/` (skipped by the Codex linker); a Skill's name never affects scope. Never hand-link a skipped Skill into the other runtime and never widen a linker's filter. Agent definitions are runtime-specific (Codex `.toml`, Claude Code Markdown with frontmatter); qlblog owns no agents today, and the first qlblog-owned agent must land under `agents/codex/` or `agents/claude/` together with linker support in the same change.
- `autoTA` and `kgdistiller` are independent product repositories and the only authorities for their Skills, workflows, agents, tests, and linkers. Do not mirror their product files in qlblog. Their linkers may coexist with qlblog links in the flat Codex Skill directory, and qlblog's linker must leave external product links untouched. Each product's Claude Code integration is currently skills-only via its `scripts/link-claude-skills.*`; product agents and workflow manifests stay Codex-only until a per-product port is explicitly requested.
- Codex-generated system Skills belong only under `$CODEX_HOME/skills/.system`; never copy, symlink, customize, publish, or version-control that directory in this repository. Claude Code has no equivalent generated directory; never invent one.
- Personal global agent guidance has one runtime-neutral authority, `install/agents/core.md`, plus one delta per runtime (`install/codex/runtime.md`, `install/claude/runtime.md`). `install/codex/AGENTS.md` and `install/claude/CLAUDE.md` are generated from those three files and committed; never edit them by hand. Run `make agents-guidance` after changing a source and `make agents-check` to verify. Each linker installs its runtime's generated file as `$CODEX_HOME/AGENTS.md` or `~/.claude/CLAUDE.md` (honoring `CLAUDE_CONFIG_DIR`) after cloning or moving the repository.
- Refreshing the knowledge instance is an explicit local authoring operation through an installed, selected kgdistiller product revision. `make knowledge-check`, ordinary site builds, and CI only validate and consume the committed export.
- Blog source lives in `site/src/content/posts/` and is exposed through `blogs/posts/`.
- Validate blog changes with `make blog-check` and `make blog-build`.
- When the user asks to install or update AI agents, read `install/agent-stack.md` completely and follow its safety contract.
- Never install a persistent daemon, gateway, scheduled task, messaging integration, or self-hosted service without explicit confirmation.
- Never place credentials in the repository or command output.
